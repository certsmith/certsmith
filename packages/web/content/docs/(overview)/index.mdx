**CertSmith** is an enterprise-ready, containerized private Certificate Authority (CA) designed to automate TLS/SSL certificate issuance and renewal across private infrastructure, homelabs, staging environments, and Kubernetes clusters using the standard **ACME v2 (RFC 8555)** protocol.

Operating as a private alternative to Let's Encrypt, CertSmith eliminates self-signed certificate warnings and complex manual OpenSSL configurations by providing standard ACME endpoints backed by multi-tier Intermediate Authorities.

---

## Why CertSmith?

In modern cloud-native architectures, securing machine-to-machine traffic with TLS is non-negotiable. However, public CAs like Let's Encrypt require public DNS control or publicly exposed HTTP endpoints, which is often infeasible or insecure for private infrastructure, internal domains (`.internal`, `.local`, `.corp`), and isolated air-gapped environments.

CertSmith solves this problem with:

- **Full ACME v2 Protocol Compliance**: Compatible with any industry-standard ACME client (Certbot, Caddy, Traefik, Lego, acme.sh, and Kubernetes `cert-manager`).
- **Cryptographic Tiering (6 CAs)**: 3 Modern Elliptic Curve (ECDSA P-256, P-384, P-521) tiers and 3 RSA (2048, 3072, 4096-bit) tiers running simultaneously.
- **Embedded Web Trust Portal**: Intuitive web dashboard providing real-time health checks, intermediate CA status, quick client configuration snippets, and one-click Root CA certificate downloads.
- **Turnkey Container Appliance**: Packaged as a lightweight, zero-maintenance Docker container powered by Step-CA, Nginx, and an ultra-fast Next.js management web layer.
- **Zero-Friction Trust Establishment**: Single Root CA distribution anchors trust across all 6 intermediate tiers, simplifying fleet-wide certificate deployment.

## System Architecture at a Glance

CertSmith is structured around a resilient two-tier PKI model:

```
                  ┌────────────────────────┐
                  │   CertSmith Root CA    │
                  │   (Long-Lived Anchor)  │
                  └───────────┬────────────┘
                              │
       ┌──────────────────────┴──────────────────────┐
       │                                             │
┌──────▼─────────────────────┐        ┌──────────────▼─────────────┐
│  ECC Family Intermediates  │        │   RSA Family Intermediates  │
│  • CE1 (ECDSA P-384)       │        │   • CR1 (RSA 4096-bit)      │
│  • CE2 (ECDSA P-256) [STD] │        │   • CR2 (RSA 3072-bit)      │
│  • CE3 (ECDSA P-521)       │        │   • CR3 (RSA 2048-bit) [LEG]│
└──────────────┬─────────────┘        └──────────────┬─────────────┘
               │                                     │
               └──────────────────┬──────────────────┘
                                  │
                  ┌───────────────▼──────────────┐
                  │      Nginx Reverse Proxy     │
                  │    & ACME v2 API Endpoints   │
                  └───────────────┬──────────────┘
                                  │
         ┌────────────────────────┼────────────────────────┐
         ▼                        ▼                        ▼
┌──────────────────┐    ┌──────────────────┐    ┌──────────────────┐
│ Certbot / acme.sh│    │ Caddy / Traefik  │    │  K8s cert-manager│
│ (Virtual Hosts)  │    │ (Edge Proxies)   │    │ (Cluster TLS)    │
└──────────────────┘    └──────────────────┘    └──────────────────┘
```
